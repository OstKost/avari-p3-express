# ADR: атомарные поколения демонстрационных данных

Дата: 2026-09-27. Статус: accepted.

## Контекст

Демо имеет SQLite-файл и manifest с ID, профилем и опорной датой. Раздельная замена файлов могла оставить новую базу со старым manifest. flock только у Python-оболочки освобождался при её SIGKILL, хотя дочерний API продолжал использовать базу. Задача: [стабилизация](../tasks/stabilization.md).

## Решение

Готовить базу, неизменяемый manifest и его копию в demo_fixture в отдельном owned поколении. После проверки SQLite и связей делать fsync файлов/каталогов и атомарно заменять current.json. API и paths выбирают поколение один раз под flock. Сохранить обычный JSON-pointer, а не symlink; запрещать symlink для входных и удаляемых файлов. API наследует descriptor flock, поэтому смерть wrapper не позволяет сбросить используемую базу.

Прямую перезапись двух файлов отвергли из-за отсутствия единого commit point. Хранение manifest только внутри базы потребовало бы изменения потребителей; текущий подход сохраняет JSON для тестов. Активная база изменяется обычными сервисами; manifest описывает исходные сценарии, а demo_fixture связывает его с поколением.

## Последствия

- reset переключает весь набор; прежние поколения и незавершённые подготовки остаются до explicit clean, что сохраняет предыдущие данные и упрощает аварийное восстановление.
- seed/api/paths проверяют версии, SQLite и соответствие manifest. Повреждённый набор требует явного reset/restore; автоматического удаления нет.
- Старый плоский layout не преобразуется без reset. Старые файлы сохраняются до clean.
- Пути выдаёт `demo.py paths`; стабильного .demo/demo.db у новых наборов нет. Ключ менеджера хранится отдельно, не входит в backup. Хеши agent_tokens остаются частью SQLite-копии.
- Backup выполняется SQLite backup API и сохраняет committed WAL страницы. Restore публикует новое полное поколение.
- Поддерживаются macOS/Linux. SIGKILL оболочки оставляет API работающим и удерживающим lock; его PID печатается для явной остановки.
- Сбой после commit point может дать nonzero exit при уже опубликованном исправном наборе. Проверяется paths; слепое удаление нового поколения запрещено.

Проверки: реальные SIGKILL до/после commit point, SIGKILL wrapper, SIGINT/SIGTERM API, ошибки записи/сборки/bind, нормализованное сравнение reset, WAL backup/restore и HTTP/UI сценарии. Гарантия fsync относится к файловым системам с POSIX rename/fsync; не обещаем поведение повреждённого диска или сетевого filesystem.
