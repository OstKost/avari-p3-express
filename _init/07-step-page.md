# Страница шага P3.express

## Назначение

Страница шага — это минимальная рабочая единица приложения. Именно здесь PM или teamlead видит, что означает конкретный шаг методологии и как он реализуется в проекте.

## Структура страницы

### 1. Breadcrumbs

Пример:
Главная / Проекты / Название проекта / P3.express / Фаза A / Шаг A04

### 2. Заголовок и описание шага

В верхней части отображаются:
- код шага;
- название шага;
- методологическое описание;
- краткое пояснение, зачем нужен этот шаг в проекте.

### 3. Блок статуса

Далее располагается статусный блок, в который входят:
- текущий статус шага;
- процент выполнения;
- дедлайн;
- наличие блокеров;
- при необходимости ответственный.

### 4. Чеклист

Главный рабочий блок страницы. Чеклист стартует от статичного шаблона P3.express, но пользователь может добавлять и удалять пункты под нужды проекта.

Каждый пункт чеклиста имеет статус выполнения. Общий процент шага рассчитывается автоматически как доля выполненных пунктов чеклиста.

### 5. Ссылки-артефакты

Вместо хранения файлов приложение хранит ссылки на внешние результаты работы. Для шага можно добавлять ссылки на:
- Jira;
- Confluence;
- GitLab;
- Structurizr;
- другие URL.

Для каждой ссылки желательно показывать:
- название;
- тип источника;
- краткий комментарий.

### 6. Комментарии

Комментарии реализуются как лента обсуждения по шагу. Это не одно поле последней заметки, а последовательность записей, где можно фиксировать решения, договорённости и уточнения.

### 7. История задач

Нижний блок страницы — история изменений и связанных действий по шагу. Здесь можно показывать изменения чеклиста, смену статуса, добавление или удаление ссылок, комментарии и другие события.

## Поведение

Страница шага должна быть максимально практичной. Пользователь должен не просто читать методологию, а реально сопровождать выполнение шага через чеклист, ссылки и историю работы.
